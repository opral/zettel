# Zettel 1 — document format

Development contract, replacing all prior Zettel representations. There is no automatic legacy migration. The schema identifier is `https://zettel.dev/schema/1/schema.json`; the schema is bundled and checked in, but this implementation does not publish a schema website.

## Document and identity

A document has exactly `_type: "zettel_doc"` and ordered `blocks`. The root has no `_key`, `$schema`, or `version`. Applications select the schema they support. In the schema file itself, `$schema` declares JSON Schema 2020-12 and `$id` identifies the schema; neither is a document field.

Every content node and annotation definition has `_type` and `_key`. Keys match `[A-Za-z0-9_-]+` and are unique across a document, including nested nodes and link definitions. `generateKey()` uses secure random UUIDs. Text edits, moves, and style changes retain identity; copies allocate new keys and remap annotation references. Markdown import allocates new identities. Keys do not supply merge semantics.

The `zettel_` type namespace is reserved. Applications can define other namespaced types through explicit extension slots. Property names need not all be prefixed. Core objects are closed. The [JSON Schema](v1.schema.json) is authoritative for shape; runtime validation also enforces uniqueness, mark references, and rectangular tables.

## Vocabulary

| Type | Content and properties |
| --- | --- |
| `zettel_block` | `style`: normal or h1–h6; inline `children`; local `markDefs` |
| `zettel_span` | Nonempty `text`; `marks` |
| `zettel_break` | Hard line break; `marks` |
| `zettel_image` | `src`, `alt`, optional `title`; `marks` |
| `zettel_html_inline` | Literal inline HTML `value`; `marks` |
| `zettel_link` | Annotation with `href` and optional `title` |
| `zettel_list` | `kind`: bullet or number; `spread`; nonempty `items`; numbered lists also require `start` |
| `zettel_list_item` | Ordered `blocks`, `spread`, optional boolean `checked` |
| `zettel_quote` | Ordered `blocks` |
| `zettel_code` | Literal `code`, optional `language` and `meta` |
| `zettel_rule` | Thematic break |
| `zettel_table` | `align` per column and nonempty `rows`; first row is the header |
| `zettel_table_row` | Nonempty `cells` |
| `zettel_table_cell` | Inline `children` and local `markDefs` |
| `zettel_html` | Literal block HTML `value` |

Paragraphs, quotes, and list items may be empty. A table must be rectangular, with one alignment entry per column (`left`, `right`, `center`, or null). Numbered list start is 0–999999999, matching Markdown's nine-digit limit. Lists may mix task and ordinary items; `checked` belongs to each item, including ordered tasks. Multiple paragraphs and nested containers belong explicitly to their item. `spread` records loose-list layout.

LF inside span text represents a soft line break; `zettel_break` represents a hard break. Markdown import can normalize source newline spelling; it must preserve the distinction between soft and hard breaks. Code and raw HTML nodes hold source content, not executable instructions.

## Marks and links

Every core inline node has `marks`, including images and breaks. Marks are an unordered set of decorator strings (`strong`, `em`, `strike-through`, `code`) and local link-definition keys. Duplicate marks, unresolved references, decorator/key collisions, and more than one link on an inline node are invalid.

Definitions live once in the enclosing text block or table cell's `markDefs`. Several differently formatted spans can share a single link. Empty link destinations and image URLs are representable because GFM allows them. Renderers apply a separate URL policy.

## GFM interchange

Use the formal GFM specification as the parsing contract. Canonical export need not preserve delimiter choice, reference-link source syntax, whitespace spelling, or node identity. It must preserve content and structure, including list-item ownership, task state, links around images, code metadata, table alignment, and raw HTML source. Conversion of arbitrary JSON extensions is not implicit: unsupported export returns an explicit diagnostic/error.

GFM raw HTML is preserved in JSON and Markdown. Default HTML rendering displays it as escaped read-only source; preservation is not permission to execute it. Full editing of arbitrary HTML is outside scope. Rich HTML clipboard paste has a separate supported-fragment conversion policy.

## Boundaries

Zettel is not Portable Text wire format, an editor's serialized state, a CRDT, an attachment store, or a comment-target format. Core schemas and node semantics are independent of Lix and Lexical. See [compatibility](compatibility.md) for extensions and [HTML contract](html-contract.md) for rendering.
